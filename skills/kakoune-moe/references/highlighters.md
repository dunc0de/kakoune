# Highlighters

Condensed reference for `add-highlighter`. Source:
`https://github.com/mawww/kakoune/tree/master/doc/pages/highlighters.asciidoc`.

## Declaration

```kakoune
add-highlighter [-override] <path>/<name> <type> [args...]
```

- `<path>`: the highlighter's location — `global`, `buffer`, `window`, or
  `shared`.
- `<name>`: a unique name for the highlighter.
- `<type>`: `regex`, `dynregex`, `fill`, `column`, `line`, `flag-lines`,
  `ranges`, `replace-ranges`, `number-lines`, `wrap`, `show-matching`,
  `show-whitespaces`, `ref`, etc.

> **Flag syntax**: `-override` is a **single-dash** flag. `--override` (double
> dash) is rejected as an unknown option.

## Regex highlighter attributes

For `regex` type, color/style is specified as `<capture_group>:<face>`:

```kakoune
add-highlighter -override buffer/myhl regex TODO 0:red
add-highlighter -override buffer/git-hl regex '^## ' 0:comment
add-highlighter -override buffer/multi-hl regex '(\w+): (.*)' 1:keyword 2:value
```

- `0:red` — the whole match in red
- `1:green` — first capture group in green
- `2:comment` — second capture group styled as comment

**Not `fg:red`** — that syntax is invalid for `add-highlighter`. Color is always
a capture-group spec (`N:<face>`), never a key-value pair.

Common faces: `red`, `green`, `blue`, `yellow`, `cyan`, `magenta`, `keyword`,
`comment`, `string`, `number`, `variable`, `value`, `error`, `warning`,
`information`, `Default`.

## Scopes

- `global` — applies across all windows of all buffers of a type.
- `buffer` — applies to a specific buffer.
- `window` — applies to a specific window.
- `shared` — shared across windows/buffers.

## Regions & passes

- `-match-capture <n>` — only highlight the Nth capture group of the regex.
- `-recurse` — allow nested matches.
- `-group <name>` — assign to a highlight group (`colorize`, `move`, `wrap`,
  `replace`, etc.) to control layering/blend order.

## `ref` highlighter

`ref` points at another highlighter by path/name so it can be shown/hidden
together with its source (e.g. toggle a custom regex highlighter and its
`number-lines` together).

## Spec-based highlighters — the timestamp rule

`flag-lines`, `ranges`, and `replace-ranges` are **spec** highlighters whose
specs are generated by `update-option`. Their spec strings **must start with
`%val{timestamp}`** so Kakoune can track changes and only repaint when the
buffer is modified:

```kakoune
add-highlighter regex my-hl %val{timestamp} ...
```

Without the `%val{timestamp}` prefix, `update-option` cannot detect changes and
the highlighter won't repaint reliably.

## Convenient builtins

- `show-matching` / `show-whitespaces` — cursor bracket / whitespace markers.
- `number-lines` — line numbers in the window gutter.
- `wrap` — line wrapping.
- `regex`, `dynregex`, `fill`, `column`, `line` — general painting.

## Update-on-change

To repaint a spec highlighter when selections/options change, wrap the spec in
`update-option` and prefix with `%val{timestamp}`:

```kakoune
update-option buffer my-spec %val{timestamp} ranges ...
```
